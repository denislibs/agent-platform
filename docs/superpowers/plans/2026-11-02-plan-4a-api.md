# План 4a: API — авторизация, задачи, файлы, SSE

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** HTTP API платформы на Hono: вход через Better Auth (Google, GitHub, magic link), создание задач, ответы на вопросы агента, отмена, загрузка и скачивание файлов, живой SSE-стрим шагов. Всё работает локально (`bun run api`) на инфраструктуре из `infra:up` и тестируется без сети и Docker там, где это возможно.

**Architecture:**
- **Новые порты ядра.** `Logger` (журнал для оператора), `Mailer` (письма magic link), `StepEvents` (уведомление «у задачи появились шаги»). У каждого — адаптер и двойник в `@agent/testing`; у `StepEvents` — ещё контрактный набор и адаптер на Valkey pub/sub в `@agent/queue`.
- **Публикация шагов после коммита.** Декораторы `PublishingStepLog` и `PublishingUnitOfWork` из `@agent/core` оборачивают `steps` и `uow` в обоих контейнерах. Запись вне транзакции публикуется сразу после `append`, запись в `uow.run` — один раз на задачу, после успешного коммита. Воркер, приём задачи, ответ и отмена публикуют без единой строчки кода публикации в сервисах.
- **Пакет `@agent/api`.** Hono-приложение `createApp(deps)` получает зависимости одним объектом (cradle контейнера). Авторизация спрятана за интерфейсом `AuthGateway`: в бою это Better Auth на Drizzle, в юнит-тестах маршрутов — `FakeAuth`. Поэтому тесты маршрутов идут на in-memory контейнере без инфраструктуры, а Better Auth проверяется отдельным интеграционным набором на Postgres.
- **SSE по схеме «уведомление, затем чтение».** Обработчик подписывается на `StepEvents`, отдаёт шаги из Postgres после `Last-Event-ID`, а на каждое уведомление и на каждый тик сердцебиения перечитывает шаги после последнего отправленного. Уведомление может потеряться без последствий: следующий тик всё равно дочитает ленту.

**Tech Stack:** Bun 1.4.2, TypeScript 7, Hono 4.13, Better Auth 1.7.15 (Drizzle-адаптер, плагин magic link), AWS SDK v3 (`@aws-sdk/client-s3`, `@aws-sdk/s3-request-presigner`) только для presigned PUT, ioredis 5 (pub/sub), zod 4, awilix 13.

Спецификация: [2026-10-31-agent-platform-design.md](../specs/2026-10-31-agent-platform-design.md), разделы 3.1, 4.2–4.4, 8, 9, 10, 11, 15. Дорожная карта: [2026-10-31-roadmap.md](2026-10-31-roadmap.md) — строка плана 4, раздел «Весь стек в Docker за nginx» и заметки «План 4 (API)». Продолжение — [план 4b](2026-11-02-plan-4b-api-stack.md): `admin:grant`, сквозной тест через API, сервисы `api` и `nginx` в compose.

## Global Constraints

- Рантайм — Bun (локально 1.4.2). TypeScript 7 strict. Перед каждым коммитом — `bun run format` и `bun run check`, без ошибок и без предупреждений oxlint.
- **Архитектура (спецификация 3.1):**
  - `@agent/core` не импортирует инфраструктуру; запрет oxlint расширяется на `@agent/api`, `hono`, `better-auth`, `@aws-sdk/*`;
  - `@agent/agent/src/**` зависит только от портов `@agent/core` и `@agent/shared`; запрет расширяется на `@agent/api`, `hono`, `better-auth`, `@aws-sdk/*`;
  - `@agent/api/src/**` не выполняет агентную логику (спецификация 3): запрет на `bullmq`, `ioredis`, `openai`, `@agent/llm`, `@agent/sandbox`, `@agent/search`, `@agent/queue`, `@agent/worker`. Job ставятся только через порт `JobQueue`;
  - `hono` и `better-auth` живут только в `@agent/api`; `@aws-sdk/*` — только в `@agent/storage`; awilix — в composition root (`@agent/composition`, `@agent/testing`, `@agent/agent/src/register.ts`, `@agent/api/src/auth/better-auth.ts` и `main.ts`).
- **TDD:** тест пишется до реализации. Все `expect(...).rejects` — с `await`. `test:unit` не требует Docker и инфраструктуры: в него входят `packages/api/test/unit`, а `packages/api/test/integration` — нет.
- **API (спецификация 10):**
  - все `/api/*`, кроме `/api/auth/*` и `/api/health`, требуют сессию; без неё — 401;
  - каждый доступ к задаче или файлу проверяет владельца; чужой, несуществующий и кривой id — одинаково 404, не 403;
  - ошибка — всегда `{ error: { code, message } }`; коды и HTTP-статусы — в «Решениях»; текст ошибок 500 наружу не уходит, он пишется в `Logger`;
  - схемы запросов и ответов — zod в `@agent/shared` (их же возьмёт веб-приложение плана 6); даты в ответах — ISO-строки.
- **Ответ пользователя (заметка дорожной карты «План 4»):** сначала шаг `message` в Postgres, потом job `currentKind` с ключом `jobKey(id, kind, lastSeq)` по `lastSeq` **после** записи ответа. Воркер пропускает первый запуск job, чей seq в ключе не равен `lastSeq` задачи; job со старым seq оставил бы задачу висеть навсегда.
- **Порядок записи (спецификация 8):** сначала шаги в Postgres (коммит), потом уведомление `StepEvents` и job. Публикация до коммита запрещена: подписчик прочитал бы ленту без этих шагов.
- **Скачивание:** только presigned GET с `Content-Disposition: attachment` — html и svg из результатов модели не открываются в нашем домене.
- **Деньги:** целые милликредиты в хранилище и в ответах (`millicredits`); кредиты для показа — строка без плавающей точки (`formatCredits`).
- Секреты не коммитятся. `.env.example` получает закомментированные заглушки, `.env.test` — только тестовые значения (тестовый `BETTER_AUTH_SECRET`). Настоящие OAuth-ключи живут только в `.env`.

## Решения и отклонения

- **Пакет — `packages/api`, а не `apps/api` (отклонение от спецификации 13):** так же лежит `packages/worker`. Веб-приложение плана 6 пойдёт в `apps/web`.
- **Better Auth на существующих таблицах `user`/`session`/`account`/`verification`** через `drizzleAdapter(db, { provider: 'pg', schema })`. Проверено на `better-auth@1.7.15` с нашей схемой и тестовой базой: вход по magic link создаёт пользователя (id — строка из 32 символов, не UUID; `millicredits` берёт значение по умолчанию 0), `auth.api.getSession({ headers })` возвращает `{ user, session }`, cookie сессии — `better-auth.session_token`. Версия закреплена точно: библиотека отвечает за безопасность входа, обновление — осознанное.
- **Провайдеры из env.** Google и GitHub включаются, только если заданы и id, и секрет приложения; задан один из пары — ошибка конфига при старте. Колбэки OAuth — `<BETTER_AUTH_URL>/api/auth/callback/google|github`. Без `BETTER_AUTH_SECRET` (минимум 32 символа) API не стартует; воркеру секрет не нужен, поэтому в схеме конфига он необязательный.
- **Доверие к прокси.** `baseURL` — статический `BETTER_AUTH_URL` (адрес nginx), поэтому заголовки прокси (`x-forwarded-host`/`proto`) не нужны: `trustedProxyHeaders` не включается. IP клиента — из `X-Real-IP` (`advanced.ipAddress.ipAddressHeaders`), который ставит nginx. API не публикуется наружу (только через nginx, план 4b), поэтому подделать заголовок клиент не может. `API_HOST` по умолчанию `127.0.0.1`: API слушает только локальный интерфейс, в compose плана 4b — адрес в сети Docker. Телеметрия Better Auth выключена.
- **Защиты Better Auth не зависят от `NODE_ENV=production`** (у самой библиотеки зависят). Проверки Origin и CSRF включены всегда (`disableOriginCheck: false`, `disableCSRFCheck: false`). Rate limiting включён везде, кроме явных `NODE_ENV=test` и `NODE_ENV=development`; пустой `NODE_ENV` считается боевым, поэтому локальный запуск — с `NODE_ENV=development` (README). Токены magic link хранятся в `verification` хэшем (`storeToken: 'hashed'`): чтение базы не даёт войти по ещё живой ссылке.
- **Журнал Better Auth — через наш `Logger`.** `createBetterAuth` и `registerAuth` получают `logger`; `betterAuthLogger` переводит журнал библиотеки на порт с очисткой: уровень warn и выше, у ошибок — только имя и текст причины, хвост `params: …` из текстов ошибок Drizzle вырезается (там токены сессий и ссылки magic link). Своим логгером Better Auth печатал бы эти ошибки целиком.
- **Пределы тел и строк.** JSON-тела `/api/*` — не больше 256 КиБ (`bodyLimit` до маршрутов), `/api/auth/*` — не больше 64 КиБ; превышение — 413 `payload_too_large`. Строки клиента (промпт, ответ, имя загружаемого файла) проверяются `noNul` (Postgres не хранит `\0` в `text`/`jsonb`, иначе был бы 500) и `wellFormed` (одиночные суррогаты ломают `jsonb`).
- **Почта — порт `Mailer`.** В этом плане есть только `LogMailer`: письмо не отправляется, а пишется в журнал, и ссылку видно в логе API. Для разработки и закрытой беты с доверенными пользователями этого достаточно. Настоящий провайдер (SMTP или HTTP API) — в backlog, выбор за владельцем продукта. Вне `NODE_ENV` test и development API предупреждает об этом в логе при старте. Тесты входят по ссылке из `CapturingMailer`, настоящего OAuth в тестах нет.
- **Авторизация за интерфейсом `AuthGateway`** (`handler(req)`, `session(headers)`). Better Auth со своим in-memory адаптером не видел бы пользователей in-memory двойников, поэтому юнит-тесты маршрутов используют `FakeAuth` с cookie `session=<token>`. Сам Better Auth проверяется интеграционными тестами на Postgres.
- **`StepEvents` и публикация после коммита.** Канал Valkey — `task:<id>` (спецификация 10), сообщение — `lastSeq` строкой. Подписчик держит одно отдельное соединение (`redis.duplicate()`, режим subscriber) на процесс, с подсчётом подписчиков на канал. Декораторы публикации живут в `@agent/core`: им нужны только порты. Сбой публикации не роняет запись (шаг уже закоммичен), а пишется в `Logger`: SSE дочитает ленту по сердцебиению.
- **SSE** (`GET /api/tasks/:id/events`, цикл — `streamTaskSteps` в `step-stream.ts`). Владелец и `Last-Event-ID` проверяются до начала потока: чужая задача — тот же 404 JSON, что и для неизвестной. Событие `step` с `id = seq` и данными `StepDto`. Когда задача в финальном статусе и все шаги отправлены, приходит событие `end` с `{ status }`, и поток закрывается: `EventSource` иначе переподключается сам. Сердцебиение — комментарий `: ping` и перечитывание ленты каждые `SSE_HEARTBEAT_MS` (15 с). Порядок: подписка, затем чтение, иначе уведомление между чтением и подпиской потерялось бы до следующего тика. Статус задачи читается до шагов: если задача уже финальная, все её шаги уже закоммичены. Шаг, дописанный воркером уже после отмены, клиент получит при следующем подключении, но не в закрытом потоке. Bun по умолчанию рвёт соединение после 10 с тишины, поэтому `idleTimeout` сервера — двойной интервал сердцебиения. `Last-Event-ID` или `?after=` — целое ≥ 0, иначе 400. API ставит `X-Accel-Buffering: no`.
  - Уведомление — только сигнал «перечитай»: `lastSeq` в нём не используется, потому что уведомления теряются и приходят не по порядку. Стрим всегда читает `seq > lastSent` из Postgres, по одному чтению за раз; уведомления, пришедшие во время чтения, схлопываются в один следующий круг.
  - `subscribe` при недоступном Valkey висит (команда ждёт в очереди ioredis), поэтому стрим ждёт его не дольше 2 с (`SUBSCRIBE_TIMEOUT_MS`), пишет предупреждение и идёт на одном сердцебиении. Подписка, пришедшая позже, подключается и сразу запускает перечитывание; пришедшая после конца стрима — тут же снимается. Отписка тоже ограничена 2 с.
  - Клиент ушёл — Bun отменяет тело ответа, Hono (`stream.onAbort`) будит цикл: отписка, таймер сердцебиения снят, чтения прекращаются. После `end` тоже не остаётся ни подписки, ни таймера. Поэтому `streamTaskSteps` получает ещё `logger` и необязательные `subscribeTimeoutMs` и `timers` (тесты считают активные таймеры) — отклонение от интерфейса задачи 11.
  - Остановка: `server.stop()` ждёт открытые соединения, а поток незавершённой задачи сам не закрывается. Маршрут учитывает потоки в `OpenStreams`; на SIGTERM `stopServer` закрывает их без `end` (EventSource переподключится к другому экземпляру с `Last-Event-ID`), ждёт штатного закрытия соединений до 5 с (`SHUTDOWN_GRACE_MS`) и затем рвёт оставшиеся `server.stop(true)`.
- **Загрузки идут из браузера прямо в S3 по presigned PUT, мимо nginx.** Отклонение от заметки дорожной карты: `client_max_body_size` nginx к файлам отношения не имеет, его хватит на JSON (план 4b ставит 1 МБ). Лимит файла `UPLOAD_MAX_BYTES` (по умолчанию 50 МиБ, как лимит чтения файла песочницы) проверяет API по объявленному размеру. S3 обеспечивает его подписью: presigned PUT подписывает `Content-Length`. Проверено на Garage v2.4.1: тело другой длины получает 403, а `PUT` по URL от Bun `S3Client.presign` подписывает только `host` и принимает любой размер. Поэтому `presignPut` делает AWS SDK (`getSignedUrl` + `PutObjectCommand` с `ContentLength`, клиент с `requestChecksumCalculation: 'WHEN_REQUIRED'`; со значением по умолчанию Garage отвечает 400). Всё остальное в адаптере остаётся на Bun `S3Client`.
- **Публичный адрес S3.** Браузер не видит `garage:3900` из сети Docker, поэтому presigned URL подписываются на `S3_PUBLIC_ENDPOINT` (по умолчанию `S3_ENDPOINT`). В разработке это опубликованный порт Garage `http://localhost:53900`, в продакшене — адрес R2/S3. CORS бакета для загрузок из браузера настраивает план 6.
- **Скачивание.** `GET /api/files/:id` проверяет владельца и отвечает `302` на presigned GET с `response-content-disposition=attachment; filename="…"; filename*=UTF-8''…`. Проверено на Garage: заголовок возвращается ровно таким, каким его подписали, включая кириллицу, кавычки и скобки в имени. Входной файл, объект которого ещё не загружен в S3, — 409 `upload_incomplete`, а не ссылка на несуществующий объект.
- **Имена загружаемых файлов.** Остаётся последняя часть пути, без управляющих и форматирующих символов (Cc, Cf — bidi-переопределения, невидимые пробелы — и U+2028/2029), без ведущих `-`, не длиннее 120 символов; пустое имя, `.` и `..` — 400. Имя — это и имя в `/workspace/inputs/` песочницы, поэтому два прикреплённых к задаче файла с одним именем — 400 `bad_request`: второй затёр бы первый.
- **`fileIds` в `POST /api/tasks`.** Повторы схлопываются. Чужой, неизвестный, уже привязанный файл или файл с `kind: 'output'` — 404 `not_found`: задача не создаётся, ничего не пишется. Файл, объект которого ещё не загружен в S3, — 409 `upload_incomplete`. API проверяет это до приёма задачи. `TaskIntake` дополнительно сверяет число привязанных файлов в транзакции и откатывает всё при гонке (`NotFoundError('file')`). Молчаливый пропуск файлов, как было в 3a, скрыл бы от пользователя, что агент работает без его данных.
- **Курсорная пагинация `GET /api/tasks`.** `?limit=1..100` (по умолчанию 20), `?before=<курсор>`. Курсор непрозрачный: base64url от `{ t: createdAt ISO, id }`. Порт получает `listForUser(userId, { limit, before })`. Postgres хранит время с точностью до микросекунд, а JS `Date` — до миллисекунд. Проверено: postgres.js отбрасывает микросекунды, не округляет. Поэтому Drizzle сравнивает и сортирует по `date_trunc('milliseconds', created_at), id`, иначе на границе страницы терялись бы задачи из той же миллисекунды. Кривой id в курсоре ведёт себя как неизвестный: пустая страница в адаптере и 400 в API.
- **Ответ на вопрос агента.** `POST /api/tasks/:id/messages` принимается только для задачи в `waiting_user` с `currentKind`, иначе 409 `conflict`. Шаг `message` пишется в транзакции, затем ставится job. Если постановка упала, ответ уже записан: API отвечает 202 и пишет предупреждение в журнал. Сборщик теперь ставит job для `waiting_user`-задачи с ответом, которая не обновлялась дольше `STALE_TASK_MS`: раньше он такие задачи пропускал, и они висели бы до тайм-аута ожидания. Ограничение: `findStale` отдаёт не больше 100 старейших ожидающих задач за проход, и при сотнях неотвеченных пауз задача с ответом может ждать. Для беты это допустимо, в backlog записано.
- **Отмена.** `POST /api/tasks/:id/cancel` переводит любую нефинальную задачу в `cancelled` (`finishedAt`, шаг `status` от `user`) одной транзакцией с `expectedFrom`. Если воркер успел сменить статус между чтением и переходом, отмена перечитывает задачу и пробует снова (до 3 раз). Повторная отмена отменённой задачи — 200 с той же задачей. Отмена `done`/`failed` — 409. Воркер остановится на ближайшей проверке `TaskGuard`, песочницу уберёт сборщик.
- **Очистка текста ошибок — в маппере API (`toStepDto`), а не в воркере.** В Postgres остаётся полный текст для оператора. Наружу у шагов `status` поле `reason` уходит без управляющих символов, абсолютные пути из двух и более сегментов заменены на `<path>`, длина не больше 200 символов.
- **Баланс в `GET /api/me`:** `{ millicredits: number, credits: string }`, где `credits` получается целочисленным делением: `12345 → "12.345"`, `1500 → "1.5"`, `-250 → "-0.25"`. Строка не теряет точность и готова к показу.
- **Коды ошибок:** `bad_request` 400 (zod, JSON, курсор, `Last-Event-ID` и `?after=`, имя файла, два прикреплённых файла с одним именем); `unauthorized` 401; `insufficient_credits` 402 (`LimitExceededError('credits')`); `not_found` 404 (`NotFoundError` и чужие id); `conflict` 409 (`InvalidTransitionError`, ответ не в `waiting_user`, отмена завершённой); `upload_incomplete` 409 (создание задачи и скачивание входного файла, объект которого ещё не загружен); `payload_too_large` 413; `too_many_active_tasks` 429 (`LimitExceededError('active_tasks')`, спецификация 4.4); `internal` 500.
- **`Logger`** — порт с `info`/`warn`/`error(message, fields)`. Боевой адаптер — `ConsoleLogger`, двойник — `CapturingLogger`. Через него пишут API, `TaskIntake` (сбой постановки `plan`) и `Sweeper` (ошибки отдельных задач и песочниц). Воркер пока пишет в `console` напрямую: перевод на порт — не в этом плане.

```ts
/** Сбой публикации не отменяет записанный шаг: подписчики дочитают ленту по своему таймеру. */
async function announce(deps: PublishDeps, taskId: string, lastSeq: number): Promise<void> {
  try {
    await deps.events.publish(taskId, lastSeq);
  } catch (err) {
    deps.logger.warn('could not announce new steps', { taskId, lastSeq, error: errorMessage(err) });
  }
}

/** Лента шагов вне транзакции: каждый append сразу после записи объявляется подписчикам задачи. */
export class PublishingStepLog implements StepLog {
  constructor(private readonly deps: PublishDeps & { inner: StepLog }) {}

  async append(input: AppendStepInput): Promise<Step> {
    const step = await this.deps.inner.append(input);
    await announce(this.deps, step.taskId, step.seq);
    return step;
  }

  list(taskId: string, opts?: { afterSeq?: number; subtaskId?: string }): Promise<Step[]> {
    return this.deps.inner.list(taskId, opts);
  }
}

/**
 * Транзакция, которая после коммита объявляет последний seq каждой задачи, получившей шаги.
 * До коммита и при откате не объявляется ничего: подписчик прочитал бы ленту без этих шагов.
 */
export class PublishingUnitOfWork implements UnitOfWork {
  constructor(private readonly deps: PublishDeps & { inner: UnitOfWork }) {}

  async run<T>(fn: (tx: TxRepositories) => Promise<T>): Promise<T> {
    const touched = new Map<string, number>();
    const result = await this.deps.inner.run(tx => fn({ ...tx, steps: collecting(tx.steps, touched) }));
    for (const [taskId, lastSeq] of touched) await announce(this.deps, taskId, lastSeq);
    return result;
  }
}

function collecting(steps: StepLog, touched: Map<string, number>): StepLog {
  return {
    async append(input) {
      const step = await steps.append(input);
      touched.set(step.taskId, Math.max(touched.get(step.taskId) ?? 0, step.seq));
      return step;
    },
    list: (taskId, opts) => steps.list(taskId, opts),
  };
}
```

```ts
      current?.delete(entry);
      if (current?.size === 0) this.handlers.delete(taskId);
    };
  }
```

```ts
import type { StepEvents } from '@agent/core';
import type { RedisConnection } from './connection';

type Handler = (lastSeq: number) => void;

/** Канал уведомлений задачи (спецификация 10). */
export const stepChannel = (taskId: string): string => `task:${taskId}`;

interface Channel {
  handlers: Set<Handler>;
  /** SUBSCRIBE этого канала: следующие подписчики ждут его, а не возвращаются раньше времени. */
  ready: Promise<unknown>;
}

/**
 * StepEvents на Valkey pub/sub. Публикация — общим соединением; подписки — одним отдельным соединением
 * на процесс (в режиме subscriber соединение не выполняет других команд), по одному SUBSCRIBE на канал
 * со счётчиком подписчиков.
 */
export class ValkeyStepEvents implements StepEvents {
  private subscriber: RedisConnection | undefined;
  private readonly channels = new Map<string, Channel>();

  constructor(private readonly deps: { redis: RedisConnection }) {}

  async publish(taskId: string, lastSeq: number): Promise<void> {
    await this.deps.redis.publish(stepChannel(taskId), String(lastSeq));
  }

  async subscribe(taskId: string, onNotify: Handler): Promise<() => Promise<void>> {
    const name = stepChannel(taskId);
    let channel = this.channels.get(name);
    if (!channel) {
      channel = { handlers: new Set(), ready: this.connection().subscribe(name) };
      this.channels.set(name, channel);
    }
    const entry: Handler = seq => onNotify(seq);
    channel.handlers.add(entry);
    await channel.ready;
    let done = false;
    return async () => {
      if (done) return;
      done = true;
      const current = this.channels.get(name);
      if (!current) return;
      current.handlers.delete(entry);
      if (current.handlers.size > 0) return;
      this.channels.delete(name);
      await this.subscriber?.unsubscribe(name);
    };
  }

  async close(): Promise<void> {
    this.channels.clear();
    const sub = this.subscriber;
    this.subscriber = undefined;
    if (sub) await sub.quit();
  }

  private connection(): RedisConnection {
    if (!this.subscriber) {
      const sub = this.deps.redis.duplicate();
      sub.on('message', (channel: string, message: string) => {
        const seq = Number(message);
        if (!Number.isSafeInteger(seq)) return;
        for (const handler of this.channels.get(channel)?.handlers ?? []) handler(seq);
      });
      this.subscriber = sub;
    }
    return this.subscriber;
  }
}
```

```ts
    const { before } = opts;
    if (before && !isUuid(before.id)) return [];
    // JS Date хранит миллисекунды, Postgres — микросекунды: сравнение и порядок — по усечённому до мс времени,
    // иначе курсор из Date на границе страницы терял бы задачи из той же миллисекунды.
    const createdMs = sql`date_trunc('milliseconds', ${tasks.createdAt})`;
    const where = before
      ? and(
          eq(tasks.userId, userId),
          sql`(${createdMs}, ${tasks.id}) < (${before.createdAt.toISOString()}::timestamptz, ${before.id}::uuid)`,

      : eq(tasks.userId, userId);
    return this.db
      .select()
      .from(tasks)
      .where(where)
      .orderBy(desc(createdMs), desc(tasks.id))
      .limit(opts.limit ?? 50);
```

```ts
   * Зависшие задачи: тот же job, что ведёт их дальше; живой job с тем же ключом очередь не повторит.
   * waiting_user с ответом: ответ записан, а его job не поставился (сбой Valkey после коммита в API) — без этого
   * задача висела бы до тайм-аута ожидания. Ключ — по lastSeq с ответом, как ставит API.
   */
  private async requeueStale(): Promise<PassResult> {
    const { tasks, queue, config } = this.deps;
    const result: PassResult = { count: 0, failed: 0 };
    const stale = await tasks.findStale({
      statuses: ['queued', 'planning', 'running', 'finalizing'],
      staleForMs: config.worker.staleTaskMs,
    });
    const waiting = await tasks.findStale({ statuses: ['waiting_user'], staleForMs: config.worker.staleTaskMs });
    for (const task of [...stale, ...waiting]) {
      try {
        const kind = await this.kindToRequeue(task);
        if (!kind) continue;
        await queue.enqueue({ taskId: task.id, kind }, jobKey(task.id, kind, task.lastSeq));
        result.count++;
      } catch (err) {
        result.failed++; // подхватит следующий проход
        this.deps.logger.warn('sweeper could not re-queue a task', { taskId: task.id, error: errorMessage(err) });
      }
    }
    return result;

    if (task.status !== 'waiting_user') return kindForStatus(task.status, task.currentKind);
    if (!task.currentKind) return undefined;
    return (await this.deps.guard.hasAnswer(task.id)) ? task.currentKind : undefined;
```

```ts
/** Милликредиты → кредиты строкой без плавающей точки (спецификация 11): 12345 → "12.345", -250 → "-0.25". */
export function formatCredits(millicredits: number): string {
  if (!Number.isSafeInteger(millicredits)) throw new RangeError(`millicredits must be a safe integer, got ${millicredits}`);
  const sign = millicredits < 0 ? '-' : '';
  const abs = Math.abs(millicredits);
  const fraction = String(abs % 1000)
    .padStart(3, '0')
    .replace(/0+$/, '');
  return `${sign}${Math.floor(abs / 1000)}${fraction ? `.${fraction}` : ''}`;
}
```

```ts
import type { AuthGateway, SessionUser } from '../src';

/** Сессии без Better Auth: cookie `session=<token>`, выданный signIn. Только для тестов. */
export class FakeAuth implements AuthGateway {
  private readonly sessions = new Map<string, SessionUser>();

  signIn(user: SessionUser): string {
    const token = crypto.randomUUID();
    this.sessions.set(token, user);
    return token;
  }

  async handler(req: Request): Promise<Response> {
    return new Response(`fake auth: ${new URL(req.url).pathname}`, { status: 200 });
  }

  async session(headers: Headers): Promise<SessionUser | undefined> {
    const token = /(?:^|;\s*)session=([^;]+)/.exec(headers.get('cookie') ?? '')?.[1];
    return token ? this.sessions.get(token) : undefined;
  }
}
```

```ts
import type { ContentfulStatusCode } from 'hono/utils/http-status';
import { InvalidTransitionError, LimitExceededError, NotFoundError } from '@agent/core';
import type { ApiErrorBody, ApiErrorCode } from '@agent/shared';

/** Ошибка с готовым ответом: статус, код и текст для клиента. */
export class ApiError extends Error {
  constructor(
    readonly status: ContentfulStatusCode,
    readonly code: ApiErrorCode,
    message: string,
  ) {
    super(message);
    this.name = 'ApiError';
  }
}

const body = (code: ApiErrorCode, message: string): ApiErrorBody => ({ error: { code, message } });

/** Ошибка → ответ. Текст неизвестных ошибок клиенту не показывается: его пишет журнал (createApp). */
export function mapError(err: unknown): { status: ContentfulStatusCode; body: ApiErrorBody } {
  if (err instanceof ApiError) return { status: err.status, body: body(err.code, err.message) };
  // Ключ не показываем: чужой id не должен подтверждаться ни в каком виде.
  if (err instanceof NotFoundError) return { status: 404, body: body('not_found', `${err.entity} not found`) };
  if (err instanceof LimitExceededError)
    return err.limit === 'credits'
      ? { status: 402, body: body('insufficient_credits', err.message) }
      : { status: 429, body: body('too_many_active_tasks', err.message) };
  if (err instanceof InvalidTransitionError)
    return { status: 409, body: body('conflict', 'the task has changed its state; reload it') };
  return { status: 500, body: body('internal', 'internal error') };
}
```

```ts
import { ApiError } from './errors';

function validate<T extends z.ZodType>(schema: T, value: unknown): z.output<T> {
  const parsed = schema.safeParse(value);
  if (!parsed.success) throw new ApiError(400, 'bad_request', z.prettifyError(parsed.error));
  return parsed.data;
}

export async function parseJson<T extends z.ZodType>(c: Context, schema: T): Promise<z.output<T>> {
  let value: unknown;
  try {
    value = await c.req.json();
  } catch {
    throw new ApiError(400, 'bad_request', 'the request body must be JSON');
  }
  return validate(schema, value);
}

export function parseQuery<T extends z.ZodType>(c: Context, schema: T): z.output<T> {
  return validate(schema, c.req.query());
}
```

```ts
const isPublic = (path: string): boolean => path === '/api/health' || path.startsWith('/api/auth/');

/** HTTP API (спецификация 10). Зависимости — одним объектом, обычно cradle контейнера. */
export function createApp(deps: ApiDeps): Hono<ApiEnv> {
  const app = new Hono<ApiEnv>();

  app.onError((err, c) => {
    const { status, body } = mapError(err);
    if (status >= 500)
      deps.logger.error('unhandled API error', { method: c.req.method, path: c.req.path, error: errorMessage(err) });
    return c.json(body, status);
  });
  app.notFound(c => c.json({ error: { code: 'not_found', message: 'no such route' } }, 404));

  app.get('/api/health', c => c.json({ ok: true }));
  app.on(['GET', 'POST'], '/api/auth/*', c => deps.auth.handler(c.req.raw));

  const authenticated = requireUser(deps.auth);
  app.use('/api/*', (c, next) => (isPublic(c.req.path) ? next() : authenticated(c, next)));

  meRoutes(app, deps);
  return app;
}
```

```ts
import { asFunction, type AwilixContainer } from 'awilix';
import { betterAuth } from 'better-auth';
import { drizzleAdapter } from 'better-auth/adapters/drizzle';
import { magicLink } from 'better-auth/plugins';
import type { MailMessage, Mailer } from '@agent/core';
import { account, session, user, verification, type Db } from '@agent/db';
import type { Config } from '@agent/shared';
import type { AuthGateway, SessionUser } from './gateway';

export const MAGIC_LINK_TTL_SEC = 15 * 60;

/** Провайдер включается, только если его приложение настроено (оба значения в env). */
export function socialProviders(auth: Config['auth']) {
  return {
    ...(auth.google ? { google: { clientId: auth.google.clientId, clientSecret: auth.google.clientSecret } } : {}),
    ...(auth.github ? { github: { clientId: auth.github.clientId, clientSecret: auth.github.clientSecret } } : {}),
  };
}

export function magicLinkMail(to: string, url: string): MailMessage {
  return {
    to,
    subject: 'Your sign-in link',
    text: `Open this link to sign in:\n\n${url}\n\nIt expires in 15 minutes. If you did not ask for it, ignore this email.`,
  };
}

/**
 * Better Auth на таблицах из @agent/db (спецификация 9). baseURL статический — адрес nginx; заголовкам прокси
 * доверяем: API наружу не публикуется. IP клиента — из X-Real-IP, который ставит nginx.
 */
export function createBetterAuth(deps: { db: Db; config: Config; mailer: Mailer }) {
  const { auth } = deps.config;
  if (!auth.secret) throw new Error('BETTER_AUTH_SECRET is not set: generate one with `openssl rand -base64 32`');
  return betterAuth({
    baseURL: auth.baseUrl,
    basePath: '/api/auth',
    secret: auth.secret,
    database: drizzleAdapter(deps.db, { provider: 'pg', schema: { user, session, account, verification } }),
    socialProviders: socialProviders(auth),
    plugins: [
      magicLink({
        expiresIn: MAGIC_LINK_TTL_SEC,
        sendMagicLink: ({ email, url }) => deps.mailer.send(magicLinkMail(email, url)),
      }),
    ],
    advanced: { trustedProxyHeaders: true, ipAddress: { ipAddressHeaders: ['x-real-ip'] } },
    telemetry: { enabled: false },
  });
}

export type BetterAuth = ReturnType<typeof createBetterAuth>;

export class BetterAuthGateway implements AuthGateway {
  constructor(private readonly auth: BetterAuth) {}

  handler(req: Request): Promise<Response> {
    return this.auth.handler(req);
  }

  async session(headers: Headers): Promise<SessionUser | undefined> {
    const found = await this.auth.api.getSession({ headers });
    if (!found) return undefined;
    const { id, email, name, image } = found.user;
    return { id, email, name, image: image ?? null };
  }
}

/** Регистрация auth в контейнере API (main.ts, интеграционные тесты). */
export function registerAuth<C extends { database: { db: Db }; config: Config; mailer: Mailer }>(
  container: AwilixContainer<C>,
) {
  return container.register({
    auth: asFunction(
      ({ database, config, mailer }: C) => new BetterAuthGateway(createBetterAuth({ db: database.db, config, mailer })),
    ).singleton(),
  });
}
```

```ts
/** Абсолютный путь хоста из двух и более сегментов: /Users/me/app, /var/run/docker.sock. */
const ABSOLUTE_PATH = /(?<![\w.~-])(?:\/[\w.@+~-]+){2,}\/?/g;

const isUnsafeChar = (ch: string): boolean => {
  const code = ch.codePointAt(0) ?? 0;
  return code < 0x20 || code === 0x7f || (code >= 0xd800 && code <= 0xdfff);
};

 * Текст ошибки для клиента: в Postgres остаётся полный (для оператора), наружу — без путей хоста и управляющих

    .trim();
```

```ts
import { errorMessage, InvalidTransitionError, type Task, type TxRepositories } from '@agent/core';
import { isTerminalTask } from '@agent/shared';
import type { ApiDeps } from './deps';
import { ApiError } from './errors';

const CANCEL_ATTEMPTS = 3;

async function reread(tx: TxRepositories, taskId: string): Promise<Task> {
  const task = await tx.tasks.get(taskId);
  if (!task) throw new Error(`task ${taskId} vanished inside its own transaction`);
  return task;
}

/**
 * Ответ на ask_user (спецификация 4.2). Сначала шаг в Postgres, потом job стадии, на которой задача остановилась,
 * с ключом по lastSeq ПОСЛЕ ответа: воркер пропускает первый запуск job, чей seq не равен lastSeq задачи (план 3d),
 * и job со старым seq оставил бы задачу висеть. Сбой постановки не теряет ответ: сборщик поставит job сам (Task 5).
 */
export async function replyToTask(
  deps: Pick<ApiDeps, 'uow' | 'queue' | 'logger'>,
  taskId: string,
  text: string,
): Promise<Task> {
  const { task, kind } = await deps.uow.run(async tx => {
    const current = await tx.tasks.get(taskId);
    if (current?.status !== 'waiting_user' || !current.currentKind)
      throw new ApiError(409, 'conflict', 'the task is not waiting for an answer');
    await tx.steps.append({ taskId, agent: 'user', payload: { type: 'message', role: 'user', text } });
    return { task: await reread(tx, taskId), kind: current.currentKind };
  });
  try {
    await deps.queue.enqueue({ taskId, kind }, jobKey(taskId, kind, task.lastSeq));
  } catch (err) {
    deps.logger.warn('could not queue the job after a reply; the sweeper will retry', {
      taskId,
      error: errorMessage(err),
    });
  }
  return task;
}

/**
 * Отмена (спецификация 8): нефинальная задача → cancelled. Воркер выйдет на ближайшей проверке статуса,
 * песочницу уберёт сборщик. Статус мог смениться между чтением и переходом — тогда перечитать и повторить.
 */
export async function cancelTask(deps: Pick<ApiDeps, 'uow' | 'clock'>, taskId: string): Promise<Task> {
  for (let attempt = 1; ; attempt++) {
    try {
      return await deps.uow.run(async tx => {
        const task = await tx.tasks.get(taskId);
        if (!task) throw new ApiError(404, 'not_found', 'task not found');
        if (task.status === 'cancelled') return task;
        if (isTerminalTask(task.status)) throw new ApiError(409, 'conflict', `the task is already ${task.status}`);
        await tx.tasks.transition(taskId, 'cancelled', { finishedAt: deps.clock.now() }, { expectedFrom: task.status });
        await tx.steps.append({ taskId, agent: 'user', payload: { type: 'status', from: task.status, to: 'cancelled' } });
        return reread(tx, taskId);
      });
    } catch (err) {
      if (err instanceof InvalidTransitionError && attempt < CANCEL_ATTEMPTS) continue;
      throw err;
    }
  }
}
```

```ts
import { ApiError } from './errors';

const MAX_NAME_CHARS = 120;

const isControl = (ch: string): boolean => {
  const code = ch.codePointAt(0) ?? 0;
  return code < 0x20 || code === 0x7f;
};

/**
 * Имя входного файла от браузера: только последняя часть пути (разделители / и \), без управляющих символов,
 * не длиннее 120 символов. Оно же — имя в /workspace/inputs/ песочницы и последняя часть ключа S3.
 */
export function safeFileName(raw: string): string {
  const last = raw.split(/[/\\]/).at(-1) ?? '';
  const name = Array.from(last)
    .filter(ch => !isControl(ch))
    .join('')
    .trim();
  const capped = Array.from(name).slice(0, MAX_NAME_CHARS).join('');
  if (capped === '' || capped === '.' || capped === '..') throw new ApiError(400, 'bad_request', 'invalid file name');
  return capped;
}

/** Имя для скачивания: последняя часть пути файла. */
export const baseName = (path: string): string => path.split('/').filter(Boolean).at(-1) ?? 'file';
```

```ts
export interface SseEvent {
  /** Имя события; комментарий (": ping") — 'comment'. */
  event: string;
  id?: string;
  data: string;
}

function parse(block: string): SseEvent {
  if (block.startsWith(':')) return { event: 'comment', data: block.slice(1).trim() };
  const event: SseEvent = { event: 'message', data: '' };
  const data: string[] = [];
  for (const line of block.split('\n')) {
    const colon = line.indexOf(':');
    const field = colon === -1 ? line : line.slice(0, colon);
    const value = colon === -1 ? '' : line.slice(colon + 1).replace(/^ /, '');
    if (field === 'event') event.event = value;
    else if (field === 'id') event.id = value;
    else if (field === 'data') data.push(value);
  }
  event.data = data.join('\n');
  return event;
}

/** Читатель потока text/event-stream для тестов: события по одному, с тайм-аутом. */
export function sseReader(res: Response) {
  const reader = res.body!.pipeThrough(new TextDecoderStream()).getReader();
  let buffer = '';

  async function read(timeoutMs: number): Promise<ReadableStreamReadResult<string>> {
    let timer: ReturnType<typeof setTimeout> | undefined;
    const timeout = new Promise<never>((_, reject) => {
      timer = setTimeout(() => reject(new Error(`no SSE data within ${timeoutMs} ms`)), timeoutMs);
    });
    try {
      return await Promise.race([reader.read(), timeout]);
    } finally {
      clearTimeout(timer);
    }
  }

  return {
    async next(opts: { timeoutMs?: number; comments?: boolean } = {}): Promise<SseEvent | undefined> {
      for (;;) {
        const end = buffer.indexOf('\n\n');
        if (end !== -1) {
          const event = parse(buffer.slice(0, end));
          buffer = buffer.slice(end + 2);
          if (event.event === 'comment' && !opts.comments) continue;
          return event;
        }
        const chunk = await read(opts.timeoutMs ?? 2000);
        if (chunk.done) return undefined;
        buffer += chunk.value;
      }
    },
    cancel: () => reader.cancel(),
  };
}
```

`packages/api/src/step-stream.ts`:
```ts
import type { Step } from '@agent/core';
import { isTerminalTask, type TaskStatus } from '@agent/shared';
import type { ApiDeps } from './deps';

/** Куда стрим пишет: SSE в бою, что угодно в тестах. */
export interface StepSink {
  readonly closed: boolean;
  onClose(listener: () => void): void;
  send(step: Step): Promise<void>;
  ping(): Promise<void>;
  end(status: TaskStatus): Promise<void>;
}

/**
 * Живая лента шагов (спецификация 10): уведомление, затем чтение.
 * 1. Подписка до первого чтения: уведомление между чтением и подпиской не потеряется.
 * 2. Статус задачи читается до шагов: если задача уже финальная, все её шаги закоммичены и попадут в это чтение.
 * 3. Ждём уведомления или тика сердцебиения; на тике — ": ping" клиенту и перечитывание (pub/sub может терять).
 * Уведомление, пришедшее во время чтения, не теряется: флаг signalled запускает ещё один круг.
 */
export async function streamTaskSteps(
  deps: Pick<ApiDeps, 'tasks' | 'steps' | 'stepEvents'>,
  opts: { taskId: string; afterSeq: number; heartbeatMs: number; sink: StepSink },
): Promise<void> {
  const { taskId, heartbeatMs, sink } = opts;
  let lastSent = opts.afterSeq;
  let signalled = false;
  let wake: () => void = () => {};
  const notify = () => {
    signalled = true;
    wake();
  };
  const unsubscribe = await deps.stepEvents.subscribe(taskId, notify);
  sink.onClose(notify);
  try {
    while (!sink.closed) {
      signalled = false;
      const task = await deps.tasks.get(taskId);
      for (const step of await deps.steps.list(taskId, { afterSeq: lastSent })) {
        if (sink.closed) return;
        await sink.send(step);
        lastSent = step.seq;
      }
      if (!task) return;
      if (isTerminalTask(task.status)) {
        await sink.end(task.status);
        return;
      }
      if (signalled) continue;
      const timedOut = await new Promise<boolean>(resolve => {
        const timer = setTimeout(() => resolve(true), heartbeatMs);
        wake = () => {
          clearTimeout(timer);
          resolve(false);
        };
      });
      wake = () => {};
      if (timedOut && !sink.closed) await sink.ping();
    }
  } finally {
    await unsubscribe();
  }
}
```

```ts
import type { Hono } from 'hono';
import { streamSSE } from 'hono/streaming';
import { errorMessage } from '@agent/core';
import type { StreamEnd } from '@agent/shared';
import type { ApiDeps, ApiEnv } from '../deps';
import { toStepDto } from '../dto';
import { ApiError } from '../errors';
import { ownTask } from '../ownership';
import { streamTaskSteps, type StepSink } from '../step-stream';

/** Last-Event-ID (переподключение EventSource) или ?after= (первое подключение клиента, у которого уже есть шаги). */
function afterSeqOf(raw: string | undefined): number {
  if (raw === undefined || raw === '') return 0;
  if (!/^\d{1,9}$/.test(raw)) throw new ApiError(400, 'bad_request', 'Last-Event-ID and ?after= must be a step number');
  return Number(raw);
}

export function eventRoutes(app: Hono<ApiEnv>, deps: ApiDeps): void {
  app.get('/api/tasks/:id/events', async c => {
    const task = await ownTask(deps.tasks, c.req.param('id'), c.get('user').id);
    const afterSeq = afterSeqOf(c.req.header('last-event-id') ?? c.req.query('after'));
    // nginx не буферизует ответ с этим заголовком (план 4b) — события уходят клиенту сразу.
    c.header('X-Accel-Buffering', 'no');
    return streamSSE(c, async stream => {
      const listeners: Array<() => void> = [];
      stream.onAbort(() => {
        for (const listener of listeners) listener();
      });
      const sink: StepSink = {
        get closed() {
          return stream.aborted || stream.closed;
        },
        onClose: listener => {
          listeners.push(listener);
        },
        send: async step => {
          await stream.writeSSE({ event: 'step', id: String(step.seq), data: JSON.stringify(toStepDto(step)) });
        },
        ping: async () => {
          await stream.write(': ping\n\n');
        },
        end: async status => {
          const body: StreamEnd = { status };
          await stream.writeSSE({ event: 'end', data: JSON.stringify(body) });
        },
      };
      // Ошибки ловим сами: onError хелпера Hono отправил бы клиенту сырой err.message.
      try {
        await streamTaskSteps(deps, { taskId: task.id, afterSeq, heartbeatMs: deps.config.api.sseHeartbeatMs, sink });
      } catch (err) {
        if (sink.closed) return; // клиент ушёл посреди записи — не ошибка
        deps.logger.error('step stream failed', { taskId: task.id, error: errorMessage(err) });
        await stream
          .writeSSE({ event: 'error', data: JSON.stringify({ code: 'internal', message: 'the stream failed; reconnect' }) })
          .catch(() => undefined);
      }
    });
  });
}
```
