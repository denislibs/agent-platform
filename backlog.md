## Блокеры перед публичным запуском

- [ ] **Прокси Docker API — не граница.** Воркер ходит в Docker через `wollomatic/socket-proxy` (`docker/docker-proxy.yml`:
      только эндпоинты песочниц, без монтирования путей хоста), не от root, с явными переменными. Тело
      `POST /containers/create` прокси не разбирает: `privileged`, `network`/`pid` host и `cap-add` проходят, `exec` —
      в любой контейнер хоста. Закрыть фильтром тела запроса (свой прокси или authz-плагин Docker) или переходом на E2B.
- [ ] **Надёжная изоляция песочниц.** Реализация `SandboxProvider` на E2B (Firecracker)
      или Docker с gVisor (`runsc`). Docker-контейнеры делят ядро хоста и не подходят
      для чужого кода от публичных пользователей.
- [ ] **Фильтрация исходящего трафика песочниц на Linux.** Правила `DOCKER-USER` в iptables/nftables хоста:
      запретить из сети `agent-sandbox` шлюз хоста, сети инфраструктуры и облачные метаданные
      (`169.254.169.254`). Сейчас это делают правила `ip rule … blackhole` внутри netns песочницы
      (проверено только на OrbStack); на сервере нужен второй, независимый от контейнера слой.
- [ ] **DNS в песочницах на Linux не проверен.** На OrbStack встроенный резолвер Docker ходит к upstream
      из netns хоста. Если демон на Linux обращается к приватному upstream из netns контейнера
      (10.x в VPC, `169.254.169.253`, роутер 192.168.x за systemd-resolved), правила `blackhole`
      сломают DNS во всех песочницах: проверить на целевом хосте или закрепить `--dns` за публичными резолверами.
- [ ] **Проверка правил egress в `get()` (по желанию).** `get()` возвращает хэндл, не проверяя правила
      `ip rule … blackhole`: контейнер, запущенный в обход провайдера, работает без них до ближайшего
      `create()`. Можно проверять или переустанавливать правила (идемпотентно, без окна) и в `get()`.
- [ ] **Квота диска для песочниц.** Лимит на том `/workspace` и на записываемый слой контейнера
      (`--storage-opt size=…` на overlay2 с xfs/pquota или отдельный том с квотой): сейчас одна задача
      может заполнить диск хоста (вместе с неограниченными скриншотами).
- [ ] **Образ песочницы по digest.** Закрепить базовый образ `node:22-bookworm-slim@sha256:…`
      и пересобирать по расписанию, а не по плавающему тегу.
- [ ] **Выход за `/workspace` по симлинкам.** `resolveWorkspacePath` проверяет путь лексически, симлинки
      внутри песочницы не разворачивает. Сейчас это сдерживает граница контейнера (хост путей
      рабочей папки не касается); пересмотреть вместе с переходом на E2B/gVisor.
- [ ] **Оплата через Stripe.** Пакеты кредитов и/или подписка, вебхуки, история платежей.
- [ ] **Продакшен-хранилище файлов.** Cloudflare R2 или AWS S3 вместо Garage (меняется только конфиг).
- [ ] **Продакшен-деплой для публичного запуска.** Бета — `docker/compose.prod.yml` на одной VM (docs/beta-checklist.md);
      дальше — несколько хостов или managed Postgres/Valkey/S3, мониторинг с метриками и алертами, автоматические бэкапы.
- [ ] **Rate limiting** на API по пользователю и IP.
- [ ] **Предел частоты `POST /api/uploads`** — в составе rate limiting: каждое объявление загрузки пишет строку `files`
      и выдаёт presigned PUT до `UPLOAD_MAX_BYTES`, сейчас без счёта.
- [ ] **Предел частоты `POST /api/tasks/:id/messages`** — в составе rate limiting: каждое сообщение на законченной задаче
      ставит job планирования и вызов модели; предела частоты нет, проверяются только лимит активных задач и баланс.
- [ ] **Срок и отзыв ссылок превью.** Ссылка несёт доступ и живёт 7–14 дней; отозвать одну нельзя: смена `PREVIEW_SECRET`
      отключит все ссылки. До публичного запуска нужны отзыв по одной ссылке и, вероятно, более короткий срок.

## Возможности агента

- [ ] Неполный список файлов от модели не даёт предупреждения: `finish` с одним файлом из многих или план, ожидавший `app.zip`, при выданном `notes.md`. Нужна проверка на реальной модели и evals (план 8 их не запускал).
- [ ] Вложения в продолжении беседы: `POST /api/tasks/:id/messages` принимает только текст, новые файлы к законченной
      задаче не прикрепить.
- [ ] Продолжение беседы с любого ответа (ветка от середины задачи), а не только с последнего.
- [ ] История версий файлов: сейчас новая версия заменяет прежнюю по тому же пути, в ленте и Library — одна.
- [ ] Снимок всей рабочей папки в S3, чтобы после удаления песочницы возвращались зависимости и невыданные файлы.
- [ ] Новый job ждёт, пока старый доработает запущенную команду (до 30 минут, `SHELL_MAX_TIMEOUT_S`). Идея: следить за
      циклом во время `runToolCall` и обрывать команду при смене цикла. «Остановить» тоже должно обрывать запущенную команду.
- [ ] Цикл job не передаётся в стадию (`executorStage.run(taskId)`, `plannerStage.plan(taskId)`): открытие заново в окне
      в миллисекунды самоисправляется только по `STALE_TASK_MS`.
- [ ] Лимит на первой проверке открытой задачи без песочницы пропускает восстановление файлов: `planLoop` выходит до
      `prepareWorkspace`.
- [ ] Файл, который агент удалил в более позднем цикле, остаётся в Library и возвращается после восстановления песочницы:
      восстанавливаются все файлы задачи из базы.
- [ ] Превью приложений с сервером и живое превью во время работы: план 10 отдаёт только выданные статические файлы, а
      проксировать порт песочницы можно лишь после надёжной изоляции.
- [ ] Превью: после продолжения беседы может открыться устаревший сайт. Точка входа выбирается по порядку путей
      (`outputs/dist` раньше `outputs/index.html`), а не по самой новой версии; предпочитать запись с самым поздним `createdAt`.
- [ ] Превью: адрес сайта выдаётся во время `finalizing`, пока файлы ещё выгружаются, и открыть можно неполный сайт.
      Выдавать адрес только для законченной задачи или после последнего файла.
- [ ] Параллельные исполнители (план 13): подзадачи без зависимостей (`depends_on`) выполняются одновременно.
- [ ] Деплой сайтов (план 11) и приложений с сервером (после надёжной изоляции) по публичной ссылке.
- [ ] Память между задачами (план 12): факты о пользователе, предпочтения, прошлые результаты.
- [ ] Мультимодальная модель для скриншотов браузера (сейчас браузер только текстом).
- [ ] Интеграции: Gmail, Google Drive, Notion, GitHub и другие; поддержка MCP-серверов.
- [ ] Подтверждение пользователем действий с внешними последствиями (нужно вместе с интеграциями).
- [ ] Задачи по расписанию.
- [ ] Свой поиск на SearXNG вместо платного API.
