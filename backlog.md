## Блокеры перед публичным запуском

- [ ] **Прокси Docker API — не граница.** Воркер ходит в Docker через `wollomatic/socket-proxy` (`docker/docker-proxy.yml`:
      только эндпоинты песочниц, без монтирования путей хоста), не от root, с явными переменными. Тело
      `POST /containers/create` прокси не разбирает: `privileged`, `network`/`pid` host и `cap-add` проходят, `exec` —
      в любой контейнер хоста. Закрыть фильтром тела запроса (свой прокси или authz-плагин Docker) или переходом на E2B.
- [ ] **Надёжная изоляция песочниц.** Реализация `SandboxProvider` на E2B (Firecracker)
      или Docker с gVisor (`runsc`). Docker-контейнеры делят ядро хоста и не подходят
      для чужого кода от публичных пользователей.
- [ ] **Фильтрация исходящего трафика песочниц на Linux.** Правила `DOCKER-USER` в iptables/nftables хоста:
      запретить из сети `agent-sandbox` шлюз хоста, сети инфраструктуры и облачные метаданные
      (`169.254.169.254`). Сейчас это делают правила `ip rule … blackhole` внутри netns песочницы
      (проверено только на OrbStack); на сервере нужен второй, независимый от контейнера слой.
- [ ] **DNS в песочницах на Linux не проверен.** На OrbStack встроенный резолвер Docker ходит к upstream
      из netns хоста. Если демон на Linux обращается к приватному upstream из netns контейнера
      (10.x в VPC, `169.254.169.253`, роутер 192.168.x за systemd-resolved), правила `blackhole`
      сломают DNS во всех песочницах: проверить на целевом хосте или закрепить `--dns` за публичными резолверами.
- [ ] **Проверка правил egress в `get()` (по желанию).** `get()` возвращает хэндл, не проверяя правила
      `ip rule … blackhole`: контейнер, запущенный в обход провайдера, работает без них до ближайшего
      `create()`. Можно проверять или переустанавливать правила (идемпотентно, без окна) и в `get()`.
- [ ] **Квота диска для песочниц.** Лимит на том `/workspace` и на записываемый слой контейнера
      (`--storage-opt size=…` на overlay2 с xfs/pquota или отдельный том с квотой): сейчас одна задача
      может заполнить диск хоста (вместе с неограниченными скриншотами).
- [ ] **Образ песочницы по digest.** Закрепить базовый образ `node:22-bookworm-slim@sha256:…`
      и пересобирать по расписанию, а не по плавающему тегу.
- [ ] **Выход за `/workspace` по симлинкам.** `resolveWorkspacePath` проверяет путь лексически, симлинки
      внутри песочницы не разворачивает. Сейчас это сдерживает граница контейнера (хост путей
      рабочей папки не касается); пересмотреть вместе с переходом на E2B/gVisor.
- [ ] **Оплата через Stripe.** Пакеты кредитов и/или подписка, вебхуки, история платежей.
- [ ] **Продакшен-хранилище файлов.** Cloudflare R2 или AWS S3 вместо Garage (меняется только конфиг).
- [ ] **Продакшен-деплой для публичного запуска.** Бета — `docker/compose.prod.yml` на одной VM (docs/beta-checklist.md);
      дальше — несколько хостов или managed Postgres/Valkey/S3, мониторинг с метриками и алертами, автоматические бэкапы.
- [ ] **Rate limiting** на API по пользователю и IP.
- [ ] **Предел частоты `POST /api/uploads`** — в составе rate limiting: каждое объявление загрузки пишет строку `files`
      и выдаёт presigned PUT до `UPLOAD_MAX_BYTES`, сейчас без счёта.

- [ ] Свой логотип и название продукта (в витрине — заглушка «agent»).

- [ ] Команды и общие рабочие пространства.
- [ ] Дополнительные OAuth-провайдеры: Apple, Microsoft и другие.
- [ ] Очередь задач пользователя сверх лимита активных вместо ответа 429.
- [ ] Админка: пользователи, кредиты, задачи (в бете — CLI `admin:grant`).
- [ ] Предел числа объявленных, но не привязанных загрузок на пользователя (вместе с rate limiting). Уборку таких файлов

- [ ] Продление сессии из охраны API: Better Auth обновляет cookie в ответе `getSession`, а охрана этот `Set-Cookie`
      не пересылает. Веб-приложение продлевает сессию само (`/api/auth/get-session` раз в 10 минут); пересылать
      cookie из охраны — по желанию.
- [ ] Скриншоты браузера в панели компьютера (спецификация 12): `screenshotPath` — путь в песочнице, API их не отдаёт.
      Выгружать `.screenshots/<callKey>.png` в S3 (с пределом числа) и отдавать через API; сейчас панель показывает текст
      снимка страницы.
- [ ] Мобильная раскладка веб-приложения: до 900 px сайдбар встаёт над содержимым, до 1100 px панель компьютера
      скрыта. Нужны шит со списком задач и вкладка «компьютер» на телефоне.
- [ ] Статусы других задач в сайдбаре обновляются только при переходах и по событиям открытой задачи: поллинг первой
      страницы или общий поток событий пользователя.
- [ ] Вход по ссылке из письма: `errorCallbackURL` тоже должен нести `next`. Сейчас битая или просроченная ссылка
      ведёт на `/sign-in?error=…` без страницы возврата, и после нового письма пользователь попадает на главную,
      а не на задачу, с которой его увела охрана.
- [ ] ui-kit: пауза тостов при наведении и фокусе (WCAG 2.2.1), поиск по первым буквам в меню и select, подменю
      в `Menu` (сейчас только стрелка в `trail`), обе темы рядом на витрине (токены по `[data-theme]` на любом
      элементе, а не только на `:root`).
- [ ] ui-kit: `Tooltip` должен оставаться при наведении на сам тултип (WCAG 1.4.13, `pointer-events`).
- [ ] ui-kit: вложенные диалоги, открытые в одном рендере, регистрируют ловушки фокуса и слои в порядке эффектов
      (сначала внешний или внутренний — зависит от того, когда панель получила ref), а не в порядке вложенности.
      Сейчас вложенный диалог открывают отдельным действием; порядок по дереву, если понадобится открывать сразу.
- [ ] Переход ui-kit и веб-приложения на Preact 11.
- [ ] **Разбор Markdown в Web Worker с тайм-аутом** (план 6, задача 7). Сейчас `Markdown` разбирает текст в главном
      потоке, а от сверхлинейных форм micromark защищают линейные пределы до разбора (`LIMITS` в
      `apps/web/src/view/markdown.tsx`: размер, строки, `*_~`, `[`, `]`, `<`, маркеры контейнеров, кусок без пробелов)
      с откатом в простой текст. Пределы закрывают только найденные формы, худший замеренный случай внутри них — около
      секунды. Надёжная защита от зависания вкладки — разбор в воркере (`worker-src 'self'` в CSP) с тайм-аутом
      (например, 200 мс; не уложился — простой текст, воркер пересоздаётся). Тогда пределы можно ослабить, и длинные
      ответы и снимки страниц перестанут терять форматирование.

## Инфраструктура и качество

- [ ] Визуальные регрессионные тесты витрины ui-kit и веб-приложения (скриншоты обеих тем) и дымовой тест витрины в Playwright (Playwright уже есть — `apps/web/playwright.config.ts`).
- [ ] Тесты клиента API веб-приложения (`apps/web/src/api/client.ts`): `getTask`, `config`, `setTheme`, `signOut`
      по отдельности (сейчас их покрывают только тесты экранов) и сетевой сбой PUT загрузки в S3 (код `network`,
      ответа хранилища нет).
- [ ] Производительность экрана долгой задачи: счётчик секунд (`useElapsed`) раз в секунду перерисовывает весь
      экран вместе с лентой — вынести тикающий счётчик в свой компонент или сигнал; каждый шаг пересчитывает
      `toolEntries`, `conversation` и `computerEntries` по всей ленте (O(n) на шаг, O(n²) на задачу) — считать
      инкрементально. Замерить на задаче в тысячи шагов.
- [ ] Тесты ui-kit: сброс модульного состояния темы (`current` в `theme.ts`) между тестами — сейчас тесты полагаются
      на порядок и вызывают `setTheme` в начале; нужен экспорт для тестов или фабрика стора.
- [ ] Тест стилей ui-kit вырезает комментарии CSS перед поиском `var(--x)`, цветовых литералов и классов: сейчас
      цвет или класс в комментарии даёт ложное падение или ложное «класс есть».
- [ ] Пароли для dev-инфраструктуры: `requirepass` у Valkey и не-дефолтный пароль Postgres
      (сейчас `agent/agent`) в `docker/compose.yml` и `.env` — вторая линия защиты, если песочница
      всё же дотянется до сервисов. В продакшен-варианте пароли Postgres и Valkey обязательны.

- [ ] Отдельный бакет S3 для тестов (сейчас тесты хранилища пишут в `agent-files` под уникальными
      ключами и удаляют их): создать его в инициализации Garage и прописать в `.env.test`; туда же — CORS сквозного
      теста веб-приложения (`http://localhost:5199`, сейчас дописывается в `agent-files`).

- [ ] Точная стоимость при дробных ценах: `costMillicredits` на границах может переплатить 1 милликредит
      из-за плавающей точки (вместе с реальным биллингом).
- [ ] Паритет адаптеров на кривом входе: дробные милликредиты, отрицательный `limit`; тест верхнего регистра
      id для всех методов репозиториев.

- [ ] Хвосты плана 3b (низкий приоритет): явная проверка полноты правил egress в конце скрипта помощника;
