## Блокеры перед публичным запуском

- [ ] **Доступ воркера к Docker — до закрытой беты.** Поставить docker-socket-proxy между воркером и Docker API:
      разрешить только те эндпоинты контейнеров, томов, сетей и exec, которыми пользуется провайдер песочниц;
      запретить `privileged`, bind-монтирование путей хоста, `pid`/`network: host`. Запускать воркер не от root
      и сузить `env_file` в `docker/compose.yml` до явного списка переменных. Сейчас `docker.sock` в контейнере
      воркера — фактически root на хосте (`cap_drop: ALL` и `no-new-privileges` этого не меняют).
- [ ] **Надёжная изоляция песочниц.** Реализация `SandboxProvider` на E2B (Firecracker)
      или Docker с gVisor (`runsc`). Docker-контейнеры делят ядро хоста и не подходят
      для чужого кода от публичных пользователей.
- [ ] **Фильтрация исходящего трафика песочниц на Linux.** Правила `DOCKER-USER` в iptables/nftables хоста:
      запретить из сети `agent-sandbox` шлюз хоста, сети инфраструктуры и облачные метаданные
      (`169.254.169.254`). Сейчас это делают правила `ip rule … blackhole` внутри netns песочницы
      (проверено только на OrbStack); на сервере нужен второй, независимый от контейнера слой.
- [ ] **DNS в песочницах на Linux не проверен.** На OrbStack встроенный резолвер Docker ходит к upstream
      из netns хоста. Если демон на Linux обращается к приватному upstream из netns контейнера
      (10.x в VPC, `169.254.169.253`, роутер 192.168.x за systemd-resolved), правила `blackhole`
      сломают DNS во всех песочницах: проверить на целевом хосте или закрепить `--dns` за публичными резолверами.
- [ ] **Проверка правил egress в `get()` (по желанию).** `get()` возвращает хэндл, не проверяя правила
      `ip rule … blackhole`: контейнер, запущенный в обход провайдера, работает без них до ближайшего
      `create()`. Можно проверять или переустанавливать правила (идемпотентно, без окна) и в `get()`.
- [ ] **Квота диска для песочниц.** Лимит на том `/workspace` и на записываемый слой контейнера
      (`--storage-opt size=…` на overlay2 с xfs/pquota или отдельный том с квотой): сейчас одна задача
      может заполнить диск хоста (вместе с неограниченными скриншотами).
- [ ] **Образ песочницы по digest.** Закрепить базовый образ `node:22-bookworm-slim@sha256:…`
      и пересобирать по расписанию, а не по плавающему тегу.
- [ ] **Выход за `/workspace` по симлинкам.** `resolveWorkspacePath` проверяет путь лексически, симлинки
      внутри песочницы не разворачивает. Сейчас это сдерживает граница контейнера (хост путей
      рабочей папки не касается); пересмотреть вместе с переходом на E2B/gVisor.
- [ ] **Оплата через Stripe.** Пакеты кредитов и/или подписка, вебхуки, история платежей.
- [ ] **Продакшен-хранилище файлов.** Cloudflare R2 или AWS S3 вместо Garage (меняется только конфиг).
- [ ] **Продакшен-деплой.** Где и как живут api, worker, web, Postgres, Valkey; бэкапы; мониторинг.
- [ ] **Rate limiting** на API по пользователю и IP.
- [ ] **Предел частоты `POST /api/uploads`** — в составе rate limiting: каждое объявление загрузки пишет строку `files`
      и выдаёт presigned PUT до `UPLOAD_MAX_BYTES`, сейчас без счёта.
- [ ] **`sanitizeReason` до беты:** вырезать и форматирующие символы (Cf: bidi-переопределения, невидимые пробелы)
      и U+2028/2029, как в именах загружаемых файлов. Сейчас из `reason` шагов `status` убираются только управляющие.

- [ ] Необязательный `questionSeq` в ответе на вопрос агента (план 6): клиент присылает seq паузы, на которую отвечает,

- [ ] Ошибки `/api/auth/*` приходят в формате Better Auth (`{ message, code }`), а не в нашем конверте

## Инфраструктура и качество

- [ ] Визуальные регрессионные тесты витрины ui-kit (скриншоты обеих тем) и дымовой тест витрины в Playwright (план 6 или 7).
- [ ] Образ бэкенда ставит рантайм-зависимости `@agent/ui` (копируется весь `packages/`, `bun install --production`):

- [ ] Пароли для dev-инфраструктуры: `requirepass` у Valkey и не-дефолтный пароль Postgres
      (сейчас `agent/agent`) в `docker/compose.yml` и `.env` — вторая линия защиты, если песочница
      всё же дотянется до сервисов.

- [ ] Отдельный бакет S3 для тестов (сейчас тесты хранилища пишут в `agent-files` под уникальными
      ключами и удаляют их): создать его в инициализации Garage и прописать в `.env.test`.

- [ ] Точная стоимость при дробных ценах: `costMillicredits` на границах может переплатить 1 милликредит
      из-за плавающей точки (вместе с реальным биллингом).
- [ ] Паритет адаптеров на кривом входе: дробные милликредиты, отрицательный `limit`; тест верхнего регистра
      id для всех методов репозиториев.

- [ ] Хвосты плана 3b (низкий приоритет): явная проверка полноты правил egress в конце скрипта помощника;
      общий таймаут тестов вместо `setDefaultTimeout` внутри контракта песочницы (`timeout` в bunfig не действует
      в bun 1.4.2); понятное сообщение при исчерпании ожидания параллельного `create()`; `.State.Status` в
      `provider.inspect`; полный список HTML-тегов в `stripHtml` (iframe, svg, form…) и схемы только http(s) для
      `BRAVE_BASE_URL`; константы 150 элементов и максимума `shell` из ядра; шире тесты управляющих инструментов.
- [ ] `file_read` по частям через `exec` (сейчас файл до 50 MiB читается целиком и режется на строки).
- [ ] Сборщик и ответы без job: за проход он видит не больше 100 старейших задач в `waiting_user`; при сотнях
      неотвеченных пауз задача с ответом, чей job не поставился, ждёт дольше. Метка «есть ответ» в `tasks` или окно
      по `updated_at` в `findStale`.
- [ ] Перевести логи воркера с `console` на порт `Logger`.

- [ ] SSE: предел числа открытых потоков на пользователя (сейчас без счёта, каждый держит соединение и подписку)
      и тики сердцебиения со случайным сдвигом — иначе потоки, открытые разом, перечитывают ленту одновременно.
- [ ] SSE: первое чтение ленты постранично. Сейчас подключение без `Last-Event-ID` к длинной задаче читает и отправляет
      все её шаги одним запросом.
- [ ] `presignGet` подписывает ещё и `response-content-type=application/octet-stream`: вместе с `attachment` это

- [ ] Сквозной тест API на Garage с кириллицей и пробелами в имени файла: `POST /api/uploads`, PUT по presigned URL,
      `GET /api/files/:id` и `Content-Disposition` скачивания (сейчас такое имя проверяет только тест `@agent/storage`
      на `presignGet`, интеграционный тест API — латиницу).
- [ ] Производительность: выражение-индекс по `date_trunc('milliseconds', created_at), id` для курсора `GET /api/tasks`

- [ ] Сборщик: тайм-аут ожидания должен проверять, что задача не возобновлялась и не ставилась на паузу заново между выборкой и переходом (сравнить `lastSeq` в транзакции). Сейчас узкое окно: свежая пауза может получить тайм-аут.
